# Library Management System (JavaFX + SQLite)

A simple **Library Management** desktop application built with **JavaFX** and **SQLite**, using **Maven** for builds.  
Development/runtime JDK is **21**, while compilation target compatibility is **Java 17** via Maven `maven.compiler.release`.  
The app uses a layered structure (`controller`, `service`, `model`, `database`, `util`) and includes **BCrypt** for password hashing.

This version includes copy-level accession tracking, improved issue/return workflows, richer book detail views, branch-scoped data behavior, and enhanced superadmin controls.

---

## Tech Stack

- **Java (runtime/dev JDK)**: 21
- **Java bytecode target**: 17 (`maven.compiler.release`)
- **UI**: JavaFX (Controls + FXML)
- **Database**: SQLite (via `sqlite-jdbc`)
- **Security**: BCrypt (`jbcrypt`) for password hashing
- **Build Tool**: Maven
- **Packaging**: Maven Shade Plugin (fat JAR)

## Current Features

### Authentication

- Login with role-based users (e.g., Admin, Librarian)
- Password hashing with BCrypt

### Superadmin Controls

- Add branch admins/librarians from Superadmin User Management
- Reset branch account passwords from Superadmin User Management
- Audit logging support for account create/reset actions (when `audit_logs` table exists)

### Books

- Add/Edit/Delete books
- Clickable book title opens a **Book Details** dialog
- Details dialog includes:
	- horizontal summary info (author, class no, total, available)
	- copy availability sheet with accession no, status, issued-to, return date
- Accession workflow supports:
	- entering a single starting accession number
	- entering copy count
	- automatic generation of accession list (e.g. `1000` + `10` => `1000..1009`)
	- duplicate checks against both in-form list and database
- QR workflow supports **one QR per accession copy**:
	- choose a specific accession copy before generating QR
	- QR payload contains title, author, selected accession, copy status, and related metadata
	- no book serial/ID field in QR payload

### Members

- Add/Edit/Deactivate/Delete members
- Filters by course, intake, type, active/inactive
- Dynamic intake options (auto-generated by year)
- Member ID behavior:
	- branch-based prefixes (e.g., `TBC`, `BMCP`, `BMCK` depending on branch code)
	- global uniqueness enforcement to match DB constraints
	- clearer save errors for ID conflicts

### Issue / Return

- Find member and book before issue
- Choose exact physical copy from available copy dropdown
- If multiple members have same/similar name, selection dialog appears with:
	- name, member ID, type, department, intake, email, phone
- Return table auto-populates with currently issued books
- Return flow calculates overdue fine and processes return

### Dashboard & Reports

- Stats cards and charts (category, monthly issue/return, member distribution)
- Monthly activity Y-axis uses whole numbers (`0, 1, 2, ...`)
- CSV report generation:
	- issued books
	- overdue books
	- inventory
	- member list
	- monthly summary

### Branch-Scoped Data Behavior

- Branch users only see and operate on their own branch data
- Copy availability data is kept consistent per branch/copy rows
- Legacy books with missing copy rows are auto-backfilled when opening copy details

## Recent Updates

- Added `book_copies` table support and issue-record copy linkage (`book_copy_id`, `accession_number`)
- Migrated issue flow to copy-level issue/return tracking
- Improved Books UI and details popup

- Updated Return tab behavior to show issued records by default
- Switched intake list from hardcoded values to dynamic year-aware generation

	- Add New Admin (validated dialog + DB save)

- Improved member registration with branch-aware ID prefixing and better conflict/error feedback
- Updated QR flow to generate per-accession QR codes (one QR = one physical copy)
- Improved copy-sheet reliability by ensuring copy records are persisted/backfilled for branch views

## Requirements

- JDK **21** installed (used by VS Code + Maven runtime)
- Maven installed (or use Maven wrapper if you add one later)

Build compatibility is configured in `pom.xml` with:

```xml
<maven.compiler.release>17</maven.compiler.release>
```

and:

```xml
<plugin>
	<groupId>org.apache.maven.plugins</groupId>
	<artifactId>maven-compiler-plugin</artifactId>
	<version>3.13.0</version>
	<configuration>
		<release>${maven.compiler.release}</release>
	</configuration>
</plugin>
```

## Setup & Run

### 1) Clone the repo
```bash
git clone https://github.com/shresthasameerman/library-management.git
cd library-management
```

### 2) Run with Maven (JavaFX plugin)
Your `pom.xml` is configured to run the app using JavaFX Maven Plugin with:

- Main class: `com.library.App`

Run:
```bash
mvn javafx:run
```

### 3) Verify Java + Maven environment

```bash
java -version
mvn -version
```

You should see Maven running on JDK 21.

## Build

### Build a runnable (fat) JAR
This project uses the **Maven Shade Plugin** to create a fat JAR during `package`.

```bash
mvn clean package
```

### Clean rebuild from scratch

```bash
mvn -q clean
mvn -q -DskipTests clean compile
```

### Force refresh after pom/config changes (VS Code + Maven)

```bash
mvn -q -U dependency:resolve
```

Then in VS Code Command Palette:

1. `Java: Clean Java Language Server Workspace` (restart when prompted)
2. `Maven: Reload Projects`
3. `Developer: Reload Window`

After build, check `target/` for the generated JAR.

> Note: the repository currently includes a `target/` directory. Usually, `target/` is not committed to Git and is added to `.gitignore`.
